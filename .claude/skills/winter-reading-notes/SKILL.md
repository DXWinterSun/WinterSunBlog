# 读书笔记：书页照片 → 高亮词句笔记 → 批注 → 放博客

2026-09-26 Winter 原话：**「我给你发书页的照片，里面会有高亮的词或短语，你能整理成笔记，
artifact 给我，我也可以批注，之后放在博客上可以做我的笔记，省得我自己写了……因为我在读
a single shot 的原著。」**

紧接着她纠正了一次，别再犯：**「不是在网页批注，是我们对话里像交付 au 章节一样的 artifact……
里面我可以直接给你批注问你问题。」**——「批注」＝ **Artifact 自带的批注功能**（选中一句 /
点卡片上的「批注」按钮 → 发给 Claude）。不要做数据库、不要做输入框、网页本身不存任何东西。

## 一句话流程

照片 → 读出每处蓝 / 粉高亮（一次一页）→ 写成笔记，追加进 `_data/reading/<书>.yml` → `render_notes.py` 生成网页 →
发布到**同一个链接** → 她在网页上批注 / 提问 → 你在批注里回她，把她的原话和答案收进那张卡 →
重新生成、重新发布 → 她说「放博客」时再排上博客。

## 文件都在哪

| 东西 | 位置 |
|---|---|
| 笔记数据（唯一真源） | `_data/reading/<slug>.yml`（A Single Shot 是 `a-single-shot.yml`） |
| 网页生成脚本 | `tools/reading/render_notes.py` |
| 固定文案 + 「先挑详略」样板卡 | `tools/reading/demo.yml` |
| 笔记网页的链接 | 数据文件里的 `book.artifact`（一本书一个链接，永远更新它） |

配色取 `_data/au_palettes.yml` 里 `book.palette` 那一套（A Single Shot 用 `Wintergreen`，
即 John Moon 的颜色），跟她看章节草稿的预览页是同一个页头样式。

## ⭐ Winter 2026-09-26 定的五条规矩（她整理好发来的原文，一条都别改）

> **一、颜色**　1. 蓝色是生词　2. 粉色是词本身认识，但这个搭配或用法值得对照、下次再看一眼的
> 3. 两种颜色不要搞混，只整理蓝色和粉色　4. 每一处标注都要整理到，不要漏
>
> **二、每条词条的顺序**　1. 词＋音标　2. 词性＋中文释义，再加一句简单的英文解释
> 3. 原文语境：只保留这个词前后几个词的短语，不要整句照抄，短语里把这个词按书上的颜色高亮；标上页码，附一句中文大意
> 4. 文中的意思和解读：方言、乡下说法、打猎用语、语气之类，有值得说的才写　5. 常见搭配、容易混的词怎么区分，有才写
>
> **三、粉色对照**　需要对照的两个用法如果隔得远，等第二个出现时再放在一起对比；第一个出现时注明“后面会对照”
>
> **四、欧路词典导入列表**　每次笔记最后附一个导入列表，标题是“📋 欧路词典导入列表（书名）”。
> 所有词排成一行、用空格隔开，一律用原形（比如 throbs 写成 throb），单独放在一个代码块里方便复制
>
> **五、防止被内容过滤拦截**　1. 一次只处理一页，这一页做完交给我，再做下一页
> 2. 任何时候都不要大段或连续摘抄原书文字

这五条在脚本里怎么落地：

| 规矩 | 怎么做 |
|---|---|
| 蓝 / 粉 | 每条写 `color: blue`（生词）或 `color: pink`（对照）。卡片右上角自动出「生词」/「对照」小牌，原文里的高亮按这个颜色上色。**其它颜色的笔迹一律不整理**；看不出是蓝是粉就写进 `unsure` 问她。书上的蓝是偏青的那支，粉还没见过——第一次见到粉笔时把 `book.highlighters.pink` 改成同色。 |
| 一处不漏 | 交稿前把照片上的每一块荧光笔数一遍，跟条数对上。 |
| 顺序 | 卡片已经按「词＋音标 → 词性＋中文＋英文 → 原文语境（页码、短语、大意）→ 解读 → 搭配 / 易混」排好，照字段填就行。 |
| 原文语境 | 字段 `context`：**只写这个词前后几个词**（通常 4–8 个英文词），不写整句；`gist` 只译这个短语。 |
| 粉色对照 | 第一个出现时写 `compare_later: true`（卡上显示“后面会对照”）；第二个出现时写 `compare: {with: "前一条的 id", text: "两处怎么不同"}`，卡上会把两处短语摆在一起。 |
| 欧路列表 | 每页末尾自动生成（带「复制」按钮），取 `lemma`，没有就取 `term`。短语拆开会变成不相干的词时，用 `eudic:` 手动指定（如 `12-gauge shotgun` 写 `eudic: gauge shotgun`）。 |
| 一次一页 | **一页＝一批**（`batches` 里一项，`pages` 就写那一页）。她一次发了好几张，也是做完一页发布一次、告诉她，再做下一页。 |

## 一、读照片

1. **一处高亮＝一条笔记。** 同一句里划了几处，就拆成几条。
2. **页码**从照片里读（页眉 / 页脚）。读不到就写 `page: ~`，并在 `unsure` 里说一声。
3. **短语一字不差**：大小写、标点、缩略（ain’t、’em）、不合语法的地方都照抄——人物说话本来就那样，
   别顺手“改对”。高亮部分用 `==…==` 包起来。
4. **看不清就说看不清**：猜出来的字写进 `unsure`，网页上会标“看不太清”请她确认。**绝不编。**
5. **绝不大段、连续地摘抄原书**：只留那几个词。翻译大意也只译那个短语，不替整段写译文。

## 二、每条笔记怎么写

一律按「详细」写（`book.detail: full`，她 2026-09-26 挑的）：

```yaml
- id: "001"                 # 三位数，全书连号；永远不改、不复用（批注锚在卡片 id 上）
  page: 7
  color: blue               # blue 生词 / pink 对照
  term: hunkered down       # 书上高亮的原样
  lemma: hunker down        # 原形，跟 term 不同时才写（欧路列表用它）
  eudic: ……                 # 可选：欧路列表里要换个写法时
  kind: 短语                # 小标：单词 / 短语 / 习语 / 俚语 / 口语 / 方言 / 一词多义 / 名物 / 语法…
  ipa: /ˈhʌŋkər daʊn/       # 美式音标
  pos: phr. v.
  cn: 蹲下身子；缩着不动     # 这里的意思，不是词典全义
  en: to squat down low     # 一句简单的英文解释，自己措辞
  context: "he ==hunkered down== behind the"   # 前后几个词，不写整句
  gist: 他在……后面蹲下身子。  # 只译这个短语
  note: ……                  # 解读：有话可说才写
  extra: ["**搭配**……", "**易混**……"]   # 有才写
  compare_later: true       # 粉色、后面还有一处要对照
  compare: {with: "001", text: "……"}    # 粉色、跟前面那条对照
  unsure: ……
  winter: ["……"]            # 她的批注，原话照录
  qa: [{q: ……, a: ……}]
```

（上面是格式示意，不是书里的原文。）

写法规矩：

- **意思只给“这里”的意思。** 常见义跟这里不一样时，在解读里点一句（“平时是……，这里是……”）。
- **解读有话可说才写**：方言和地方口语、俚语、乡下说法、不合语法的原因、打猎 / 枪械 / 农活之类的
  名物、文化背景、双关、语气。没什么可说的就空着，别凑字数。
- **拿不准的方言、俚语、名物先查证**，查不到就写“拿不准”，别编。
- ⚠️ **别剧透**：她还在往后读。解读只谈这一页和之前的内容，**绝不提后面的情节、结局、人物下场**。
- 解读用中文写，**不中英夹杂**：英文只出现在被解释的词、短语和必要的对照词本身。
- 引号用弯引号 “ ”；页码、编号用阿拉伯数字。

## 三、生成、发布

```bash
python3 tools/reading/render_notes.py _data/reading/a-single-shot.yml -o <scratchpad>/a-single-shot-notes.html
```

- **一本书只有一个链接。** 新的一批往 `batches` **末尾**追加（`n` 递增），重新生成，发布到同一个链接：
  - 同一个对话里：用同一个 `file_path` 再发布即可；
  - 换了对话：先 `Artifact(action="read", url=book.artifact)`，再带 `url=book.artifact` 发布。
  - 旧的批次一个字都别挪——批注是锚在页面上的，前面的东西一动，旧批注就对不上位置。
- **第一次发布**要带 `capabilities: {"comments": {"composer_only": true}}`：卡片上的「批注」按钮
  靠它打开批注框。之后重新发布**不传** `capabilities`，保持原样。新书第一次发布后把链接写进 `book.artifact`。
- 数据里还没有任何一批时，页面显示样板卡（`demo.yml`）；有了第一批，样板自动让位。
  `book.detail_picked: true` 时样板只留她选的那一版（「以后都照这个样子记」），否则三版并排让她挑。
  **开新书时她的偏好已经定了**：直接写 `detail: full` + `detail_picked: true`，不用再让她挑一遍。
- 聊天里只给链接和几句人话（这一批几条、哪几条看不清要她确认），**不把笔记贴进聊天框**。
- 数据文件、脚本的改动跟着工作分支提交；`_data/reading/` 目前没有任何页面在用，推不推 main 都不影响线上。

## 四、她批注、提问之后

她把批注发给 Claude（「Send to Claude」或在批注里 @Claude）时，正在看这张页的对话会被唤醒。
换了对话，先用 `ArtifactComments(action="watch", url=…)` 接上；没被唤醒时也可以
`ArtifactComments(action="read", url=…)` 主动去读。每次：

1. 读全部批注，按锚点 / 引文对上是哪张卡（卡片 id 是 `n001` 这样的）。
2. **提问** → 在那条批注里直接回答：中文、简短、说人话，别剧透。有用的问答收进那张卡的 `qa`。
3. **批注 / 感想** → 原话一字不改收进那张卡的 `winter`（她写了几条就几条）。别替她润色，也别替她写。
4. **指出错误**（意思不对、原句抄错、页码不对）→ 改数据，在批注里回一句改了什么。
5. **定下偏好**（「就这版」「以后不要音标」「高亮换粉色」）→ 改 `book` 里的设置，并记进本文件第六节。
6. 重新生成、发布到同一个链接；回完、改完的批注串标成已解决（只能解决「发给了 Claude」的那些；
   没发给 Claude 的，告诉她哪几条还开着）。
